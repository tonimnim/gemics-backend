## Limits and next gate

The [runbook](production-like-loadtest.md) records the exact commands, regression
test and generator topology. The SQL fix and smoke gate are complete; the burst
must be judged by all-player success, not merely healthy dependencies.

Next capacity gate: run an externally hosted staging API with distributed,
high-bandwidth generators and measured available bandwidth. Repeat first-attempt
and retry-enabled tests separately, retain safe transport-phase diagnostics, and
test real Kenyan mobile-network clients with retry/backoff and indeterminate PUT
recovery. Measure a deliberately filled 1,000-job verification queue and tune
worker replica count from drain-time results. No additional hosted service was
provisioned or purchased during this task.

Even a successful burst here will not certify production HA: this is one laptop
and one network link, with local HTTP/plaintext internal service connections,
asynchronous replication without automatic failover, and simulated email. Backup
restore, managed-service failover, TLS, secret scopes, distributed load generation
and actual mobile-client behavior need separate acceptance tests.
